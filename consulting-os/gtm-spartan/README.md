# GTM Spartan

Go-to-market, on most small firms, is a founder with a tab open.

They hunt when they remember. The list is a graveyard in a spreadsheet. Applications get written at 11pm in the voice of whoever is tired. Tools get bolted on — a scraper here, a sequencer there — and suddenly the firm has risk, not a pipeline.

GTM Spartan is the organization's **how we find work** function. Three stations, one loop: **hunt → list → apply**. Specialist agents on the spokes. The coordinator at the hub. **Human-in-the-loop** before anything becomes a name, a list, or a send.

Vendor APIs only. No marketplace scrape. No cookies. No auto-submit. The OS scores and drafts. A person still clicks.

## How the loop works

**Hunt** finds the pain shape. Cards. Patterns. Why this fits Audit → Install → Operate. No person names. The principal marks keep or skip. Hunt is not allowed to promote itself into a worked list.

**List** runs only on keeps. Candidate prep: enough context to work the row, in one live working file. That's the difference between research and a mess.

**Apply** drafts against a listing. First line is their pain, in their words. Then what you'd install, how the method runs, a short ask. The draft sits in a queue. Submit is a human action.

## Architecture

The same interface sits behind every board and every source. Swap the adapter, keep the loop. Scoring, HITL, never-submit — those don't change when the source does.
